# DevTools Grimoire: план записи и объяснения производительности

## Цель и принцип интерфейса

Пользователь проходит путь «действие в приложении → событие → затронутые компоненты → возможное объяснение → сравнение после правки». Основная карта остаётся обзором архитектуры и активности. Подробности открываются в отдельной панели **Анализ**, чтобы пульсации и печати не превращались в таблицу чисел.

Каждая цифра помечается источником: **Profiler**, **наблюдатель React Fiber**, **lifecycle Vue** или **наблюдение браузера**. Длительность React Profiler относится к поддереву; длительность Vue lifecycle может включать детей; DOM-мутация не считается рендером. Изменённый prop, state или реактивный ключ называется «наблюдаемым изменением». Причина без подтверждённой связи называется «возможной связью». Не складывать вложенные длительности поддеревьев как независимую стоимость.

## Как пользователь читает экран

| Вопрос | Где ответ | Что именно видно |
| --- | --- | --- |
| Подключено ли приложение? | Полоса под заголовком панели | Зелёная точка, React/Vue, режим браузера или адаптера и число активных страниц. Если сигнал старше 90 секунд, показывается отсутствие активного подключения. |
| Что произошло после клика? | «Запись и события» | Синяя точка действия, охристые точки обновлений, красная точка долгой задачи; группа содержит число событий и временную привязку. |
| Какой компонент обновился? | Карточка события и карта | Имя, путь в дереве, родитель и прямые дети того же React commit, кнопка перехода к печати. |
| Можно ли доверять связи с печатью? | Строка «Сопоставление» | «Точное», «по имени или пути», «несколько кандидатов» или «не найдено». При неоднозначности пользователь выбирает печать вручную и может отменить выбор. |
| Стало ли лучше? | «Сравнение» и «Библиотеки» | Изменение числа обновлений и среднего времени между двумя записями; изменение оценённого JS-веса между двумя ручными сборками. Разные источники времени вызывают предупреждение. |

У каждой категории постоянный цвет и текстовая подпись: цвет не единственный способ различить событие. Панель открывается поверх карты, а не закрывает её навсегда: переход к печати возвращает пользователя на карту. На узком экране фильтры переносятся на новую строку, таблицы прокручиваются по горизонтали, а карточка события располагается под списком. Пустые состояния сообщают следующее действие: начать запись, включить обновлённый адаптер или выполнить второе измерение.

## Сценарии использования

1. **Первое подключение.** Grimoire определяет фреймворк проекта. Пользователь добавляет `dev:grimoire` кнопкой, запускает эту команду в проекте и видит в панели тип активного источника. Для уже подключённого проекта интерфейс предлагает «Обновить адаптер», если сгенерированный код устарел; после обновления нужен перезапуск dev-сервера проекта.
2. **Поиск частых обновлений.** Пользователь нажимает «Начать запись», воспроизводит одно действие и останавливает запись. Выбирает крупную группу на шкале, затем компонент. Карточка показывает факты: какой prop поменялся по ссылке, был ли замечен state или Vue key, какие дети обновились в том же commit. Путь на карте помогает найти код. Формулировка не объявляет родителя виновником только потому, что он тоже обновился.
3. **Проверка исправления.** Пользователь записывает тот же сценарий после правки. Два сохранённых сеанса выбираются как «До» и «После». Таблица сортируется по изменению числа обновлений. Средние времена представлены отдельно и сопровождаются типом измерения; при разных источниках вывод о времени считается ограниченным.
4. **Тяжёлая библиотека.** Пользователь выбирает «Измерить Vite-сборку». Раздел библиотек показывает оценённые JS-байты в начальной загрузке и ленивых чанках. После изменения импортов пользователь запускает второе измерение и получает дельту. Из строки можно открыть соответствующую печать на карте.
5. **Неизвестный элемент.** Пользователь нажимает «Выбрать в приложении», возвращается к локальной странице и кликает нужный элемент. Grimoire показывает найденный компонент и точность сопоставления. Через 30 секунд режим выбора выключается сам.

## 1. Сопоставление runtime с картой

- Адаптеры передают идентификатор экземпляра компонента в текущей странице, ID родителя, файл при наличии и ID страницы. Для React наблюдатель использует dev-источники Fiber, если они доступны; для Vue — `__file` и UID экземпляра. Это помогает различать одинаковые имена в разных ветках.
- Клиент сначала сопоставляет явный ID печати, затем файл и имя, затем уникальное имя. Неоднозначные события остаются в записи. Пользователь может выбрать печать для конкретного runtime-экземпляра; выбор сохраняется в текущей сессии.
- В панели показывать долю сопоставленных событий и конкретные причины пропусков: неизвестное имя, неоднозначное имя, отсутствующий файл. Сброс связи доступен рядом с выбранным соответствием. ID экземпляра действителен только в пределах текущей страницы; ручной выбор не переносится молча на другое приложение.

## 2. Запись сценариев

- Кнопки **Начать**, **Остановить**, **Очистить текущую запись**. Запись создаётся только после явного нажатия. События без записи продолжают отображаться в живой сводке.
- Ограниченный буфер и счётчик отброшенных событий защищают интерфейс от переполнения. Сохранённые сессии содержат только типы событий, имена, ключи и времена; значения props/state и текст пользовательского ввода не собираются.
- До пяти сессий одного проекта сохраняются в браузере; экспорт и импорт JSON позволяют перенести результат. Импорт проверяет формат и размер. Сессии другого проекта не смешиваются автоматически.
- Основной экран сессии: временная шкала по действиям пользователя и commit, список событий, фильтры по источнику/типу/компоненту. Нажатие на событие показывает путь родителей и потомков в том же commit.

## 3. Объяснение обновления

- Карточка события содержит компонент, путь в дереве, фазу, длительность и источник замера. Ниже — изменившиеся props/state или реактивные ключи. Рядом с каждой строкой — тип доказательства: наблюдение, временная связь, гипотеза.
- Внутри React commit события группируются по ID страницы и commit. Дочерние длительности показываются отдельно без суммирования с родителем. Для Vue сохраняется дерево экземпляров; близость событий по времени показана на шкале и не выдаётся за React commit.
- Кнопка **Показать на карте** выделяет печать и перемещает камеру. Для неоднозначного события показываются кандидаты для ручного сопоставления.

## 4. Действия пользователя и время браузера

- Зонд и dev-адаптер регистрируют клики и клавиши без значения ввода: тип действия, время и краткий CSS-идентификатор элемента. `PerformanceObserver` собирает длительные задачи; Event Timing используется при поддержке браузера.
- Лента связывает действие с последующими обновлениями по ID взаимодействия, когда он доступен, иначе по ограниченному временному окну с пометкой «по времени». Это не доказывает причинность.
- Визуально: горизонтальные группы «действие», «обновления», «долгая задача». Отдельные подписи для задержки браузера и длительности компонента исключают их смешение.

## 5. Граф реактивности Vue

- Dev-hook `renderTracked` и `renderTriggered` передаёт ID реактивной цели, ключ и тип операции без значений. Количество ключей на компонент ограничено.
- Представление «ключ → компоненты»: слева ключи, справа использующие их компоненты; событие-триггер выделяется цветом. Из любого компонента можно перейти к печати.
- Если Vue dev-hook недоступен, панель показывает это прямо и оставляет lifecycle-события.

## 6. Сравнение библиотек

- Каждый запуск **Измерить Vite-сборку** создаёт снимок размеров для выбранного проекта. Сравнение показывает изменение оценённых выпущенных JS-байтов по каждой библиотеке и изменение распределения «начальная загрузка / ленивые чанки».
- Визуально: таблица печатей с «было», «стало», «разница»; увеличение выделяется охрой или красным, уменьшение — зелёным. По клику открывается библиотека на карте.
- Это распределённая оценка по Rollup-модулям, а не точный gzip-размер или стоимость выполнения. Измерение по-прежнему запускается только по кнопке.

## 7. Выбор элемента в приложении

- Кнопка **Выбрать в приложении** включает один режим выбора на подключённой локальной странице. Следующий клик на элементе определяет компонент через Vue/React dev-маркеры, отправляет событие и выключает режим.
- В Grimoire показываются состояние ожидания, найденный компонент, точность сопоставления и переход к печати. Если не получилось определить компонент, показывается причина и путь ручного поиска.
- Режим выбора не считывает текст элемента и отменяет выбранный клик, чтобы случайно не выполнить действие приложения. Команда истекает автоматически.

## Порядок реализации и критерии готовности

1. Расширить контракт телеметрии и приём на локальном сервере; сохранить совместимость со старыми адаптерами.
2. Добавить сопоставление, диагностику покрытия и ограниченную запись сессий.
3. Сделать панель анализа с подробностью события и сравнением сессий.
4. Добавить события взаимодействий, Vue-ключи и выбор элемента в приложении.
5. Сохранять снимки Vite-измерений и показывать сравнение библиотек.
6. Проверить сборку пакетов и отсутствие изменений в целевом проекте. Существующие подключения получают новые возможности после обновления сгенерированного адаптера и перезапуска `dev:grimoire`; старый протокол остаётся читаемым.

Готовый интерфейс должен отвечать на четыре вопроса без обращения к логам: **есть ли подключение, что произошло, насколько точен вывод и изменилась ли ситуация после правки**.

## Границы измерения и устойчивость

- **React 17, 18, 19:** наблюдение Fiber использует внутренний dev-hook React, поэтому при изменениях внутреннего протокола может перестать давать дерево. В этом случае остаются Profiler для обёрнутых поддеревьев и браузерные сигналы. `actualDuration` относится к поддереву, поэтому строки commit нельзя сложить и назвать общим CPU-временем.
- **Vue 3:** lifecycle-измерение показывает интервал между хуками, а `renderTracked`/`renderTriggered` сообщает ключи реактивности только в dev-режиме. Ключи позволяют увидеть связь с обновлением, но не заменяют трассировку всей причинной цепочки.
- **Браузерный режим:** DOM-изменение и long task доступны без правки приложения. Это наблюдение, а не число рендеров компонентов. UI отделяет такие события от точных обновлений.
- **Память и приватность:** клиент держит максимум 1500 событий на запись, пять сессий и пять снимков сборки на проект в локальном хранилище браузера. Передаются имена компонентов, имена props/ключей, время и краткий идентификатор тега; значения state/props и содержимое полей ввода не передаются.
- **Сбой подключения:** при исчезновении heartbeat статус меняется на «Нет активного подключения» без потери уже сохранённой записи. Переключение проекта сбрасывает живые счётчики и загружает только относящиеся к нему сессии. Несопоставленные события остаются доступными в списке для разбора.
