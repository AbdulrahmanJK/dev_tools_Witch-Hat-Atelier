## Важные границы текущей версии

- Кнопка установки адаптера поддерживает стандартный Vite entry. «Любой проект» пока означает возможность статически просканировать проект; автоматическое изменение точки входа для любого сборщика ещё не реализовано.
- Быстрый браузерный режим видит DOM и долгие задачи, но не является измерением рендера компонента.
- React Fiber — внутренний dev-интерфейс. Изменённый prop, state или обновление родителя — наблюдаемые признаки, а не доказанная первопричина. Времена вложенных поддеревьев не складываются.
- Оценка веса библиотек распределяет выпущенные JS-байты Vite/Rollup. Она не равна gzip-размеру, времени загрузки или runtime CPU.
- Записи находятся в localStorage текущего браузера: максимум пять сессий на проект и 1500 событий в каждой. Есть экспорт и импорт JSON.
- Пользователь подтвердил работу на `upline_admin-module`; последние оптимизации после этого подтверждены сборкой и проверкой синтаксиса адаптеров, но их влияние на нагрев Mac пока не измерено.
- Статическая карта Go/Java/Kotlin/C# использует лёгкий синтаксический проход. Она не заявляет точного разрешения типов и вызовов; для этих языков нет runtime DevTools. Большие проекты показывают этапы сканирования и ошибки, а файловое слежение отключается после 5000 исходников.

## Приоритеты дальше

### 1. Стабилизация и измерения — ближайший рубеж

На одном повторяемом сценарии записать путь «действие → адаптер → локальный сервер → карта» и измерить задержку события и загрузку CPU/GPU. Проверить поведение после скрытия вкладки, масштабирования карты, длинной записи и потока быстрых commit. Отдельно пройти React 17, 18, 19 и Vue 3 на небольших эталонных проектах. Исправить пропуски и дубли до добавления новых источников данных. Поставить рядом с задержкой в интерфейсе источник измерения и счётчик потерянных событий.

### 2. Понятная причинная цепочка ререндеров

Сделать в карточке commit путь «действие → первый наблюдаемый изменившийся компонент/ключ → затронутое поддерево». Отдельно показывать подтверждённое наблюдение, временную связь и гипотезу. Уточнить идентификацию одинаковых компонентов по файлу и пути в дереве. Не выдавать корреляцию родителя и ребёнка за доказанную причину. Для React учитывать контекст и внешние store только при наличии надёжного источника, для Vue — явно показывать доступность dev-хуков.

### 3. Более полезное сравнение

Сравнивать две записи по одному сценарию и одному источнику замера; подсвечивать новые, исчезнувшие и наиболее изменившиеся компоненты. Для сборки добавить точный размер сжатого результата по чанкам и разделить «начальная загрузка» и «загружается позже». Действующая кнопка измерения остаётся единственным запуском сборки целевого проекта.

### 4. Подключение большего числа проектов

После стабилизации Vite добавить явные адаптеры для других типовых сборщиков и нестандартных entry. Перед изменением проекта показывать конкретный diff, сохранять безопасное удаление и отсутствие автоматического запуска. Для неподдерживаемых случаев оставлять браузерный зонд и ручной адаптер с ясной инструкцией.

### 5. Завершение продукта

Проверить полный русский и английский интерфейс, маленькие экраны, доступность с клавиатуры и обозначения на далёком масштабе. Решить, нужен ли паритет runtime-функций в VS Code webview или достаточно ссылки на локальный web-интерфейс. Зафиксировать публичный формат экспортируемых сессий и миграцию при его изменении.

## Дополнение: реализация плана больших проектов

В рабочем дереве добавлены обнаружение приложений/workspaces и сборщика, счётчик покрытия разбора, восстановление импорта и видимых компонентов из файлов с ошибками Babel, кэш разбора неизменённых файлов, пространственный индекс для наведения, выбор перекрывающихся печатей, кэш далёкой карты и раскладки, сжатие графа для передачи браузеру, выбор подпапки для слежения, импорт готовых Webpack stats и установка React Fiber hook в выбранный Webpack entry с предварительным просмотром изменений. Vite-установка и измерение теперь выбирают конкретное приложение в monorepo. Это наличие кода, а не подтверждение на Calypso.

Добавлено безопасное автоматическое подключение Vue 3 к Webpack, когда в выбранном клиентском entry найден один вызов `createApp` и `mount`; при неоднозначности установка отказывает и предлагает ручной адаптер. Кэш раскладки теперь хранит геометрию отдельно от текста и диагностики: при неизменной структуре карты новые данные узлов берутся из свежего скана, а координаты восстанавливаются без повторной упаковки.

Для Webpack добавлен запуск обнаруженного stats-скрипта по отдельной кнопке после просмотра команды, рабочей папки и пути результата. Во время выполнения видны журнал и кнопка остановки; действует лимит 15 минут. Результат импортируется из ожидаемого `stats.json`.

Остаются: инкрементальный пересчёт связей и раскладки при изменении структуры графа и замеры CPU/памяти на Calypso. Большой проект повторно не сканировался и сборка его не запускалась.
