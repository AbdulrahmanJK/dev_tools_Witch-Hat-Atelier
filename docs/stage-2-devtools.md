# Руководство по DevTools Grimoire: React 17–19, Vue 3 и библиотеки

Grimoire показывает структуру проекта и помогает искать проблемы с обновлениями компонентов. Есть два источника данных:

- **Статический анализ** работает сразу после сканирования исходников. Он находит компоненты, импорты, циклы, возможные риски ререндеров и библиотеки. Это гипотезы по коду, а не измеренная нагрузка.
- **Runtime-наблюдение** появляется после подключения запущенного приложения. Оно показывает события обновления компонентов, длительность доступных замеров и место компонента в дереве. Возможности зависят от способа подключения.

Сканер определяет фреймворк по импортам, JSX, Vue SFC и `package.json`. Если установленную версию React или Vue удаётся прочитать, он показывает её; иначе использует диапазон из зависимостей. Для Vue 3 SFC применяется компилятор Vue. Находки React и Vue содержат файл, строку, правило и уровень уверенности.

## Быстрый запуск

1. Из корня Grimoire запустите сервер для нужного проекта:

   ```bash
   node packages/cli/bin/wha-viewer.js /абсолютный/путь/к/проекту
   ```

2. Откройте адрес, показанный CLI, и включите **DevTools**.
3. Откройте **Runtime и библиотеки**. Для Vite выберите приложение и нажмите **Добавить команду DevTools**. Для React или Vue 3 с Webpack выберите приложение, dev-команду и клиентский entry, затем нажмите **Показать изменения** и **Добавить DevTools**.
4. В папке анализируемого проекта запустите `npm run dev:grimoire` или аналогичную команду вашего пакетного менеджера. Откройте приложение и выполните действия, которые хотите исследовать.
5. Вернитесь к карте Grimoire. Сводка покажет обновления компонентов и события по дереву. Нажмите на компонент, чтобы открыть его инспектор.
6. Если нужен вес библиотек в итоговом JS, для Vite отдельно нажмите **Измерить Vite-сборку**. Для Webpack можно указать путь к готовому `stats.json` и нажать **Импорт**. Если в выбранном приложении найден stats-скрипт, его также можно запустить из сводки после просмотра команды и ожидаемого файла.

На большой карте каждый компонент остаётся отдельной цветной отметкой. При приближении появляется подробная печать. Кнопка **Вместить карту** показывает границы проекта; при клике по плотному месту можно выбрать нужный компонент из ближайших кандидатов. При повторном сканировании неизменённые файлы берутся из кэша разбора, а статус показывает количество полностью и частично разобранных файлов. Если геометрия карты не изменилась, координаты берутся из кэша раскладки, а информация о коде и диагностике обновляется. Для проекта с более чем 5000 исходниками слежение за всем репозиторием выключено. В карточке статуса можно выбрать подпапку до 5000 исходников и включить слежение за ней. Для остальных изменений нажмите **Обновить карту**.

Кнопка **−** сворачивает сводку DevTools до небольшой плашки. Нажатие на плашку открывает её снова; выбор сохраняется в браузере. Поиск в шапке показывает упорядоченные совпадения по названиям компонентов, модулей, библиотек и путям файлов. Ввод текста не меняет текущий выбор: выберите результат мышью или клавишей Enter, чтобы переместиться к печати. Переключатель **Русский / English** меняет язык основных элементов интерфейса. Кнопка **Знаки** объясняет формы печатей, цвета, диагностические кольца и пульсации.

## Панель «Анализ DevTools»

Нажмите **Открыть анализ** в сводке или значок ◈ на её свёрнутой плашке. Панель разделена на четыре вкладки:

Верхняя полоса показывает, есть ли активное подключение, его источник и количество страниц. Сигнал обновляется примерно раз в 30 секунд; через 90 секунд без сигнала подключение считается неактивным. Если данные рендеров есть в истории, но сигнал исчез, запись остаётся доступной для просмотра.

1. **Запись и события** — начните запись, выполните действия в приложении и остановите её. Временная шкала различает действия, обновления и долгие задачи. Карточки под шкалой группируют события в течение секунды после действия; это связь по времени, а не доказанная причина. Выберите событие, чтобы увидеть путь компонента, источник длительности, изменившиеся props/state или ключи Vue и соседей в том же React commit. Вложенные длительности поддеревьев не суммируются.
2. **Сравнение** — сопоставьте две сохранённые сессии по числу обновлений и средней длительности на компонент. Для содержательного результата повторите одинаковый сценарий в одинаковых условиях.
3. **Связи Vue** — посмотрите, какие реактивные ключи отслеживались компонентами и какие запускали обновления. Панель заполняется после обновления Vue-адаптера и записи сессии; значения реактивных объектов не передаются.
4. **Библиотеки** — сравните два снимка Vite или Webpack stats по оценённому вкладу каждой библиотеки в JS. Видно, относится ли пакет к начальной загрузке или ленивым чанкам. Источник и приложение подписаны; разные источники или приложения не считаются точным сравнением. Vite-сборка запускается только кнопкой измерения, Webpack stats читается из существующего файла.

До пяти сессий текущего проекта сохраняются в браузере. Буфер одной записи ограничен 1500 событиями; число пропущенных из-за лимита показано в панели. Запись можно экспортировать и импортировать как JSON. Файл другого проекта или неверного формата не принимается. В панели также показана доля сопоставленных событий. Если одинаковые имена компонентов дают несколько кандидатов, выберите правильную печать вручную; для событий с ID runtime-экземпляра этот выбор применяется к экземпляру в записи. Ручную связь можно сбросить из карточки события.

Кнопка **Выбрать в приложении** на 30 секунд включает режим выбора на подключённой локальной странице. Нажмите на элемент в целевом приложении: его обычный клик будет отменён, а Grimoire попробует открыть соответствующую печать. Для этой функции требуется свежий адаптер или браузерный зонд. Если установленная версия адаптера устарела, в панели **Runtime и библиотеки** появится **Обновить адаптер**. После обновления перезапустите `dev:grimoire` и перезагрузите приложение. Обновление проверяет, что сгенерированные файлы не были изменены вручную.

## Что означают показатели

Сводка разделяет **повторные обновления компонентов**, **первые mount** и **наблюдения DOM**. Изменение DOM само по себе не доказывает ререндер компонента. Золотое кольцо обозначает обновление, зелёное — mount или изменение DOM, красная пульсация — частые события Profiler. Размер пульсаций задаётся в экранных координатах, поэтому они видны и при отдалённой карте. Метка **Горячие** требует минимум пяти измеренных обновлений со средней длительностью более 16 мс.

Список недавних событий показывает путь в дереве компонентов и замеченные изменения props/state. Изменение ссылки prop, состояния или активность родителя — наблюдаемый сигнал, но само по себе оно не доказывает причину замедления. Если имя компонента неоднозначно, событие остаётся в списке, но Grimoire не привязывает его к конкретной печати.

Диагностика **Границы / Pact** выделяет импорты из `src/components` в `src/pages` или `src/views`. Красная нить и ссылка на строку позволяют проверить нарушение архитектурной границы. Это правило не считает ошибкой любой импорт между разными папками.

Каждая импортируемая внешняя библиотека показана печатью на основной карте. До сборки её оценка основана на распространённости импортов по исходникам, а не на байтах бандла. Нажмите на печать, чтобы увидеть модули, которые её импортируют. Динамические импорты учитываются отдельно.

## Подключение runtime

### Автоматическое подключение Vite-проекта

Кнопка **Добавить команду DevTools** работает для выбранного Vite-приложения со стандартной точкой входа: модуль в `index.html` либо `src/main`/`src/index`. В monorepo сначала выберите приложение. Grimoire находит корневой рендер React 17–19 или `createApp` Vue 3, добавляет удаляемую обёртку в точку входа, создаёт `.grimoire/adapter.js`, `.grimoire/adapter.d.ts` и `.grimoire/run.mjs`, затем добавляет `dev:grimoire` в `package.json` выбранного приложения.

Добавление команды **не устанавливает зависимости, не запускает приложение и не выполняет сборку**. Запускайте приложение из его каталога через `npm run dev:grimoire` или соответствующую команду pnpm/yarn. Runner сохраняет существующую dev-команду Vite и включает инструментирование через `VITE_GRIMOIRE=1`. При обычном запуске dev-команды и при production-сборке телеметрия неактивна.

**Удалить подключение** удаляет созданную команду и обёртку. Перед удалением Grimoire проверяет, что сгенерированные фрагменты и файлы не были изменены, и не затрагивает остальные правки. Из интерфейса можно изменять только проект и его workspaces, выбранные при запуске CLI. Если Vite entry нестандартный, доступны ручной адаптер и браузерный зонд.

### React и Vue 3 + Webpack в monorepo

В разделе **Runtime и библиотеки** выберите обнаруженное React- или Vue-приложение с Webpack, его существующий dev-скрипт и клиентскую точку входа. Путь entry указывается относительно корня просканированного проекта. Если Grimoire не нашёл entry автоматически, укажите его вручную. Кнопка **Показать изменения** перечислит строки и файлы, которые будут добавлены. Для React установка создаёт `.grimoire/fiber-hook.js` и импорт hook. Для Vue 3 она создаёт `.grimoire/vue-adapter.js` и оборачивает единственный распознанный `createApp(...)`, чтобы установить dev-mixin до `mount`. Оба варианта добавляют `.grimoire/run.mjs` и команду `dev:grimoire`. Установка не запускает исходную dev-команду.

После установки запустите показанную команду из каталога выбранного приложения. **Важно:** Webpack-инструментирование работает в локальной development-сборке после установки и при обычной dev-команде этого приложения; production-сборка его выключает. `dev:grimoire` запускает обнаруженный dev-скрипт, поэтому перед запуском посмотрите его текст: в крупном monorepo он может выполнять подготовку или сборку. React hook использует внутренний Fiber и показывает дерево обновлений; для публичного React Profiler при необходимости используйте ручную обёртку ниже. Vue-адаптер измеряет lifecycle обновления каждого компонента и наблюдаемые реактивные ключи. **Удалить DevTools** проверяет сгенерированные файлы и удаляет только свои изменения. Если порт Grimoire изменился, нажмите **Обновить адрес** и перезапустите dev-сервер приложения.

Для Vue 3 с несколькими `createApp`, нестандартным импортом или отдельным mount-модулем автоматическая установка откажет с объяснением; используйте ручной Vue-адаптер или браузерный зонд. Для приложения на нестандартном локальном адресе добавьте при запуске Grimoire `--allow-origin http://имя.localhost:порт`. Указывайте точный origin без пути; сервер продолжает слушать только `127.0.0.1`.

Для старой установки React, сделанной до появления трассировки компонентов, показывается кнопка **Добавить иерархию компонентов**. После нажатия перезапустите `dev:grimoire` и обновите страницу приложения. Обновление добавляет dev-наблюдатель Fiber перед импортами React: он считывает положение каждого зафиксированного компонента в дереве родителей, поверхностные изменения ссылок props, наблюдаемые изменения state и доступную длительность поддерева. Наблюдатель использует внутренние поля React Fiber в версиях 17–19, поэтому нестандартные рендереры или обёртки компонентов могут быть пропущены. Подход учитывает идеи React DevTools и React Scan, но не заменяет их полный набор возможностей.

### Браузерный зонд и ручные адаптеры

В панели **Runtime и библиотеки** есть команды для копирования:

- **Браузерный зонд**: вставьте скрипт в консоль DevTools страницы целевого приложения. Он наблюдает изменения DOM и долгие задачи основного потока. Когда возможно, он использует маркеры React Fiber или Vue на DOM-узлах для связи наблюдений с компонентами. Этот режим не измеряет длительность рендера компонента. Остановить его можно командой `window.__grimoireQuickProbe.stop()`.
- **Адаптер Vue 3**: импортируйте `installGrimoireVue` по локальному URL адаптера в точке входа приложения и вызовите `installGrimoireVue(app)` до `app.mount(...)`. Глобальный mixin записывает интервалы lifecycle для mount/update и доступные в dev-режиме ключи, вызвавшие рендер. Интервалы могут включать работу дочерних компонентов и не равны изолированному CPU-времени функции рендера. Само инструментирование добавляет накладные расходы.
- **Адаптер React 17–19**: ручной `profileReact` оборачивает корень или отдельный элемент публичным API React Profiler и сообщает фактическую длительность обёрнутого поддерева. Автоматическое подключение использует описанный выше наблюдатель Fiber, чтобы находить компоненты по всему дереву. Для точного замера отдельного поддерева публичным Profiler используйте `profileReactComponent(React, Component, import.meta.url)` в модуле этого компонента. URL файла помогает сопоставить печать при одинаковых именах. Передаются имена изменившихся props и категории изменений ссылки/значения; сами значения props не отправляются.

События поступают на локальный сервер и затем на карту. Grimoire сопоставляет событие с печатью по ID узла либо по уникальной паре имени компонента и файла. Локальный сервер слушает loopback и принимает телеметрию от `localhost`, `127.0.0.1` и адресов, явно разрешённых через `--allow-origin`. Если обёртка React фиксирует изменение ссылки prop, найденного статическим анализом JSX у родителя, инспектор помечает находку как наблюдавшуюся в runtime и показывает последнюю длительность поддерева. Это подтверждает изменение ссылки во время измеренного commit, но не доказывает, что именно этот prop вызвал ререндер или что мемоизация поможет.

Runtime-подключение и кнопка измерения сборки доступны в локальном CLI/web-интерфейсе. Webview расширения VS Code пока показывает статический граф и печати библиотек.

## Измерение библиотек и ограничения оценки

**Измерить Vite-сборку** запускается только по нажатию. Grimoire выполняет Vite-сборку целевого проекта с плагином Rollup в памяти. Отчёт использует `renderedLength` каждого модуля и распределяет размер итоговых чанков пропорционально этим длинам. По статическим импортам чанков от точек входа определяется, относится ли библиотека к начальному пути загрузки.

После измерения кольцо печати библиотеки отражает **оценку выпущенного JavaScript**: зелёный цвет — менее 20 KiB, охра — от 20 до 100 KiB, красный — 100 KiB и больше. В инспекторе показаны численная оценка и принадлежность к начальному пути. Сводка показывает сумму оценок по измеренным библиотекам, долю начальной загрузки и самые тяжёлые пакеты. Эта сумма **не равна размеру всего приложения**. Оценка также не равна точному объёму скачивания, сжатому размеру, времени разбора JS или нагрузке во время работы.

Сборка записывает результат в каталог, настроенный в выбранном Vite-приложении. Для Webpack кнопка импорта принимает готовый JSON stats внутри проекта (до 120 МБ) и распределяет размер JS-чанков между библиотеками пропорционально `module.size`; это оценка, а не точный вклад после сжатия. Если в stats нет `modules`, `chunks` или `assets`, Grimoire объяснит причину отказа. При наличии stats-скрипта в `package.json` выберите приложение, скрипт и путь к ожидаемому `stats.json`, нажмите **Показать команду**, проверьте рабочую папку и содержимое скрипта, затем нажмите **Запустить измерение**. Журнал и состояние видны в сводке, **Остановить сборку** прекращает процесс, лимит выполнения — 15 минут. Адаптер и браузерный зонд сами не запускают dev-сервер или сборку.
