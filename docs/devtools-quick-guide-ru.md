# DevTools Grimoire: короткое руководство

DevTools показывает статические находки в коде и события запущенного приложения. Runtime-подключение доступно для React 17–19 и Vue 3. Для Go, Java, Kotlin и C# пока есть только статическая карта.

## Запуск и подключение

1. Из корня Grimoire выполните `node packages/cli/bin/wha-viewer.js "/путь/к/проекту"` и откройте адрес из терминала.
2. Нажмите **DevTools → Runtime и библиотеки**.
3. Для **Vite** выберите приложение и нажмите **Добавить команду DevTools**. Для **Webpack** выберите приложение, исходную dev-команду и клиентский entry, затем нажмите **Показать изменения → Добавить DevTools**.
4. В каталоге выбранного приложения запустите `npm run dev:grimoire` (или команду pnpm/yarn). Откройте приложение и выполните действия, которые хотите исследовать. Точную команду и файл подключения показывает окно Grimoire.

Кнопка подключения меняет файлы целевого проекта, но сама не запускает приложение. Чтобы убрать интеграцию, нажмите **Удалить подключение** или **Удалить DevTools** в том же окне. Если автоматическое подключение не подходит, **Скопировать браузерный зонд** даёт быстрый вариант через консоль браузера: он видит изменения DOM и долгие задачи, но не даёт точной иерархии ререндеров.

## Как читать интерфейс

| Элемент | Что делать |
| --- | --- |
| **Сводка DevTools** | Смотреть обновления, монтирования, DOM-события, активные компоненты и последние события по дереву. Кнопка **−** сворачивает сводку. |
| **Печать на карте** | Нажать для инспектора: файл, строка, статические находки, runtime-метрики и связи. **Вся карта** подбирает масштаб; поиск находит компонент, модуль или библиотеку. |
| **Кольца активности** | Золотое — обновление компонента; зелёное — mount или DOM; красное — частые события. DOM-событие само по себе не означает ререндер. |
| **Фильтры сверху** | **Циклы**, **Мёртвый код**, **Границы**, **Горячие** помогают найти соответствующие проблемы. **Знаки** объясняют символы и цвета. |
| **Лёгкая карта** | Оставляет названия и основные связи, убирает мелкие знаки и анимацию для слабого компьютера. Повторное нажатие возвращает подробную карту. |

## Анализ событий и библиотек

Нажмите **Открыть анализ → Начать запись**, выполните сценарий в приложении и нажмите **Остановить и сохранить**. Во вкладке **Запись и события** выберите событие на шкале: справа появятся компонент, длительность, путь и доступные причины обновления. **Выбрать в приложении** помогает найти печать по элементу страницы. Вкладка **Сравнение** сопоставляет две записи; **Связи Vue** показывает реактивные ключи; **Библиотеки** сравнивает снимки веса пакетов.

Для оценки размера библиотек нажмите **Измерить Vite-сборку**. Для Webpack импортируйте готовый `stats.json` в сводке или сначала просмотрите команду обнаруженного stats-скрипта и запустите измерение кнопкой. Сборка запускается только по нажатию. Показанный размер — оценка вклада библиотек в JS, а не полный размер приложения или объём сетевой передачи.

Если событие помечено как **предположительное** или **неоднозначное**, сопоставление с файлом не подтверждено. В карточке события можно выбрать правильный компонент вручную. Связь действия пользователя с последующими рендерами по времени не доказывает причину обновления.
