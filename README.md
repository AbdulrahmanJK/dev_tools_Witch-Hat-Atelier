# ✧ Grimoire: Witch Hat Atelier Codebase Architectural Viewer ✧

Архитектурный визуализатор кодовых баз в аутентичной стилистике манускриптов манги Камомэ Сирахамы **«Ателье колдовских колпаков» (Witch Hat Atelier / とんがり帽子のアトリエ)**.

---

## ✦ Возможности

- **Каноническая геометрия :**
  - Печати (Замкнутые круги — *Boundary Rings*), Стрелы направления потоков данных (*Directional Arrows*), Символы операций и функций (*Operant Runes*), Радиальные ключевые замки (*Radial Keystone Crowns*).
  - Гексагональные печати классов и компонентов.
  - 3-уровневое концентрическое зонирование (Annular Zoning) без визуальных пересечений и коллизий связей.
- **Два режима визуализации:**
  - **Manga Art Mode:** аутентичный монохромный манускрипт тушью на состаренном пергаменте.
  - **Interactive Mode:** интерактивный интерфейс с живой пульсацией потоков данных, подсветкой родословных связей (Lineage Mandala) и инспектором файлов.
- **Производительность:**
  - Canvas 2D с перерисовкой по событиям и ограниченной частотой фоновой анимации; вкладка в фоне останавливает цикл отрисовки.
  - Вьюпорт-куллинг и 3-уровневый LOD (Level of Detail).
- **Архитектура Монорепозитория:**
  - `packages/core`: сканирование AST (Babel), построение графа зависимостей, расчет метрик, алгоритмы упаковки печатей (Apollonian circle packing).
  - `packages/canvas-engine`: независимый движок рендеринга на Canvas 2D.
  - `packages/web`: интерфейс на React 19 + Vite + Zustand.
  - `packages/cli`: CLI-утилита локального запуска с SSE live reload.
  - `packages/vscode-extension`: интеграция в VS Code через Webview.

## ✦ Примеры интерфейса

### Арт-режим: вся карта

![Общая карта в арт-режиме](docs/images/art-mode-overview.png)

**Вся карта** помещает проект на экран. Приближайте область колесом мыши или найдите компонент через поиск.

### Арт-режим: подробные печати

![Подробные печати и знаки исходника](docs/images/art-mode-seals.png)

Знаки показывают найденные конструкции: например, три `useEffect` добавляют три знака на ободе. Внутренние знаки состояния и эффектов объединяют группы; у плотных печатей есть два кольца. Количество и список смотрите в инспекторе.

### Цветная карта

![Компоненты, модули и их связи](docs/images/architecture-map-detail.png)

Цвета и символы помогают различать части проекта. Линии показывают связи, **LOC** — количество строк исходника.

### DevTools: обзор

![Общая карта в режиме DevTools](docs/images/devtools-map-overview.png)

Фильтры выделяют циклы, кандидатов в мёртвый код и другие находки. **Показать сводку** раскрывает счётчики.

### DevTools: подробная карта

![Диагностические ободы и подробные печати](docs/images/devtools-map-detail.png)

Нажмите печать, чтобы открыть находки в инспекторе. Отключите **Подробную карту**, чтобы убрать мелкие знаки и анимации на слабом компьютере.

### DevTools: запись событий

![Запись событий и дерево компонентов React](docs/images/devtools-event-analysis.png)

Подключите приложение через **Runtime и библиотеки** и запустите `dev:grimoire`. Нажмите **Начать запись**, выполните действие и нажмите **Остановить и сохранить**. Выберите событие для просмотра длительности, дерева и изменений. **Не найдено** означает отсутствие сопоставления с печатью; **Отброшено из буфера** — неполную запись.

### Инспектор и дочерние компоненты

![Выбранный компонент и его связи](docs/images/component-connections-inspector.png)

Нажмите печать: связи подсветятся, справа появится инспектор. Имена в разделе **Внутренние знаки** позволяют перейти к найденным дочерним печатям. Это состав компонента по исходнику, а не список текущих ререндеров.

## ✦ Быстрый старт

### Требования
- Node.js >= 18
- pnpm >= 9

### Установка и сборка
```bash
# Установка зависимостей
pnpm install

# Сборка всех пакетов
pnpm run build

# Запуск тестов
pnpm test
```

### Запуск веб-интерфейса разработки
```bash
pnpm run dev
```

## ✦ Инструкция: Как открыть любой другой проект через Grimoire Viewer

Можно визуализировать локальные проекты на React, Vue, Node.js, TypeScript/JavaScript, Go, Java, Kotlin и C#.

Для Go (`.go`), Java (`.java`), Kotlin (`.kt`, `.kts`) и C# (`.cs`) доступна **статическая карта**: печати типов и функций, список методов, полей и свойств, сигнатуры, строки исходника и импорты. Runtime DevTools для этих языков скрыты. Это начальный разбор исходников: сложные языковые конструкции могут быть распознаны неполно; связи вызовов и точное разрешение типов пока не строятся. Java/Kotlin импорты связываются с локальными символами только при однозначном совпадении полного имени.

Для React 17–19 и Vue 3 доступны статические DevTools, наблюдение в браузере и адаптер для dev-сборки. Сборка Vite запускается только кнопкой **Измерить Vite-сборку**; для Webpack можно импортировать готовый `stats.json` или явно запустить обнаруженный stats-скрипт после просмотра команды.

Для типового Vite-проекта кнопка **Добавить команду DevTools** в панели **Runtime и библиотеки** добавляет команду `dev:grimoire` и подключает адаптер к точке входа. Для React или Vue 3 + Webpack выберите приложение, entry и dev-скрипт; интерфейс покажет изменения перед установкой. Кнопка удаления убирает созданную интеграцию.

Панель **Анализ DevTools** записывает сценарии, показывает цепочки обновлений, сравнивает сессии и Vite-сборки, отображает реактивные связи Vue и помогает выбрать компонент прямо в приложении.

### Вариант 1. Через CLI-команду

Передайте абсолютный путь к папке нужного проекта в команду:

```bash
node packages/cli/bin/wha-viewer.js /путь/к/вашему/проекту
```

Например, для проекта в папке `Documents`:
```bash
node packages/cli/bin/wha-viewer.js /path/to/sample-project
```

Сервер станет доступен по адресу `http://localhost:4173` (или на ближайшем свободном порту); откройте адрес из терминала в браузере. Сканирование AST, связей и размещение карты идут в отдельном потоке. На странице видны этап, число обработанных файлов, время без обновлений и журнал ошибок. В терминале этапы и ошибки также выводятся по мере работы. Кнопка **Остановить** прерывает сканирование, **Повторить сканирование** запускает его снова.

Сканер обходит весь указанный проект, включая папки `packages`, `client` и корневую `src`. На карту попадают исходники JavaScript, TypeScript, Vue, Go, Java, Kotlin и C#, включая тестовые файлы. Каталоги зависимостей и результатов сборки, стили, документы и изображения исключаются из этой карты.

На Windows запускайте те же команды в PowerShell, заключая пути с пробелами в кавычки. Например:

```powershell
pnpm.cmd install
pnpm.cmd run build
node packages/cli/bin/wha-viewer.js "C:\projects\sample-project"
```

Для проектов с более чем 5000 исходными файлами автоматическое слежение за всем репозиторием отключается, чтобы не нагружать компьютер дополнительным обходом каталогов. В карточке статуса можно выбрать подпапку до 5000 исходников для слежения; остальные изменения подтягиваются кнопкой **Обновить карту**. Для меньших проектов работает автоматическая перезагрузка при изменении кода.

Если dev-сервер приложения открыт на собственном локальном домене, разрешите его точный origin при запуске Grimoire:

```bash
node packages/cli/bin/wha-viewer.js /путь/к/проекту --allow-origin http://app.localhost:3000
```

### Вариант 2. Глобальная ссылка через pnpm / npm

Вы можете связать команду локально:
```bash
pnpm link --global
```
После этого из папки любого проекта достаточно выполнить:
```bash
wha-viewer .
```
или указать порт:
```bash
wha-viewer . --port 4000
```
